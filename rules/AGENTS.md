# Clean MIUI AI — Safety & Workflow Rules

Always follow these non-negotiable guardrails when helping a user clean, declutter, or restore their Android / MIUI / HyperOS phone with Clean MIUI AI:

1. **Existing OS Only — Never Flash or Root:** Never suggest or execute bootloader unlocking, rooting, recovery flashing, custom ROM installation, or system partition mounting. Every operation must stay strictly on the existing stock OS via standard ADB (`pm`, `settings`, `appops`, `wm`) or documented phone Settings menus.
2. **Mandatory Backup + Dry-Run Verification First:** Before disabling, uninstalling for `user 0`, or modifying any setting/appop/density, run `python scripts/inspect_and_backup.py` and verify the snapshot with `python scripts/restore.py --backup-dir <dir> --dry-run`. State honestly what ADB backups cover (APKs, package states, recorded settings/appops/wm density) and cannot cover without root (private `/data/data` app data).
3. **Hard Protection List Cannot Be Bypassed:** Never remove or disable core Android, SystemUI, Google Play Services, Telephony, Settings, Package Installer core, MIUI/HyperOS Security Center/Updater/Find Device/Account core, the **currently active Home launcher**, or the **currently active Keyboard IME**. Rely on `scripts/apply_changes.py` (which enforces `scripts/safety.py` and live device checks) instead of ad-hoc `adb shell` mutation commands.
4. **Never Leave a Missing Core Function:** Before proposing removal or disabling of any OEM browser, file manager, keyboard, calculator, dialer, messages app, or calendar, confirm via `scripts/analyze_backup.py` (or live package check) that a working replacement (e.g., Chrome, Files by Google, Gboard, Google Calculator, Google Calendar) is already installed and enabled on the device.
5. **Explicit User Approval Gate:** Always run `scripts/analyze_backup.py --emit-draft-plan plans/draft_plan.json`, present a clear grouped Markdown summary (Tier A safe bloat/ads vs. Tier B optional Google Stock style vs. AppOps/Settings vs. Protected/Excluded), note Xiaomi caveats honestly (`Install via USB`, `USB debugging (Security settings)`, Global Settings menu stubs), and **wait for explicit user confirmation** before writing `"approved": true` and running `scripts/apply_changes.py`.
6. **Verify Before Declaring Done & Keep Privacy Clean:** After applying changes, run `python scripts/verify_device.py` and inspect its actual output. Never commit or save personal device serials, Wi-Fi IP addresses, `backups/` snapshots, `.apk` binaries, or personal screenshots into tracked repository files.
